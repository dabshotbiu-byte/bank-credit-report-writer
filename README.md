# 对公授信报告生成技能

`bank-credit-report-writer` 是一个面向商业银行对公授信业务的 Codex Skill。它可以结合企业基础资料、公开信息、财务报表、科目余额表、银行流水、发票及业务合同，协助完成有事实依据、可供审查的授信尽职调查报告。

技能的重点不是简单整理材料，而是建立完整的授信分析链条：

> 业务模式 → 产品结构 → 客户 → 供应商 → 行业分析 → 竞争态势与竞争对手 → 核心竞争力 → 财务表现 → 现金流验证 → 风险判断与授信方案

## 核心能力

- 按既有 Word 模板和行文风格撰写授信报告，并尽量保持原有章节、表格和版式。
- 无指定模板时，按内置的小企业或复杂结构范本骨架生成。
- Word 成稿的可编辑文字统一采用楷体，三级标题统一为“一、大标题 → 1.中标题 → 1）小标题”。
- 查询企业登记、股权、司法、知识产权、融资和经营动态等公开信息，并记录来源与查询日期。
- 建立完整产品清单，逐产品分析应用场景、具体应用、产品构成、交付方式、定价及收入确认、毛利来源和营运资金周期；相同模式的产品仅在有明确依据时合并分析。
- 每个产品或有效产品组均绘制业务模式图，其中资金流使用红色箭头，货物、服务或数据流使用黑色箭头，并在正文解释资金占用影响。
- 分析资产负债表、利润表和现金流量表的规模、结构、趋势及异常变化。
- 从科目余额表中识别重大科目，并下钻至前五大明细及往来对象。
- 对银行流水进行逐笔归类，剔除内部划转、融资流入、股东投入、关联方资金往来、理财赎回、利息、退款等非真实销售回款。
- 通过合同、发票、银行流水、应收账款和收入账面数据进行交叉验证。
- 形成风险点、缓释措施、还款来源和授信方案之间相互对应的审查逻辑。

## 快速开始

在提示词开头调用技能，并写明申报主体、金额、品种、期限、用途和材料位置。例如：

```text
$bank-credit-report-writer

请根据 /path/to/company-materials 目录内的材料，为某科技有限公司申报
人民币1,000万元综合授信，期限1年，用于日常经营周转。

请使用 /path/to/report-template.docx 作为报告模板，完成：
1. 企业及股权背景调查；
2. 主营业务和各产品的业务场景、业务模式及具体应用分析；
3. 客户、供应商、行业、竞争对手和核心竞争力分析；
4. 财务报表、重大科目和前五大明细分析；
5. 银行流水核查及真实销售回款测算；
6. 业务模式图、风险判断、还款来源和授信方案；
7. 输出完整 Word 授信报告及必要的核查底稿。
```

如果暂时没有完整材料，也可以先让技能制作材料清单：

```text
$bank-credit-report-writer

请根据拟申报的1,000万元流动资金授信，为制造业企业制作一份尽调材料清单，
并按“必需材料、重点验证材料、补充材料”分类。
```

## 建议提供的材料

材料越完整，报告中的交叉验证越充分。建议至少提供：

- 授信报告模板及历史报告样例；
- 营业执照、公司章程、股权结构和实际控制人资料；
- 企业介绍、产品资料、业务流程及组织架构；
- 主要客户和供应商清单、合同、订单、发票及物流或验收凭证；
- 最近三年及最近一期财务报表；
- 最近一期科目余额表和重大科目明细账；
- 主要结算账户近一年银行流水；
- 纳税申报、开票、征信、融资及对外担保资料；
- 本次授信用途、金额、期限、还款来源及担保方案。

请在提示词中说明材料的统计口径、币种和截止日期。扫描件模糊、表格缺页或不同材料口径不一致时，最好同时提供原始电子表格。

## 标准工作流程

1. 建立证据清单，区分企业材料、公开来源、测算结果和分析判断。
2. 建立产品清单，按模板逐产品完成场景、应用、构成、模式、图示、客户、供应商、竞争和现金流分析。
3. 查询企业、股东、关联方、客户、供应商和竞争对手的公开信息。
4. 分析财务趋势、重大科目、前五大明细和异常波动。
5. 清洗银行流水，测算可识别销售回款并与收入、开票和应收账款交叉验证。
6. 绘制逐产品业务模式图，形成行业、竞争力、风险和还款来源判断。
7. 使用产品覆盖矩阵检查是否存在遗漏，再按模板生成报告并完成事实一致性、数字勾稽、措辞和版式检查。
8. 对成稿执行楷体、三级标题、禁用措辞及模板字段完整性检查，再逐页渲染复核。

正式报告会直接陈述已核实事实并完成“事实—原因—现金流影响—授信判断”的论证，不使用“官网显示”“公司提供的材料里显示”“建议补充”“需核实”等让报告显得未完成的表述。公开来源及查询日期保留在核查底稿、脚注或表注中。

## 辅助脚本

仓库内置四个辅助脚本。建议在复制出的工作目录中运行，保留原始材料不变。

银行流水和科目余额表脚本需要 Python 3，以及 `pandas`、`openpyxl`、`xlsxwriter`：

```bash
python3 -m pip install pandas openpyxl xlsxwriter
```

### 银行流水初步分类

```bash
python3 scripts/review_bank_flows.py bank-flows.xlsx bank-flow-review.xlsx
```

脚本会生成流水分类和汇总底稿。自动分类仅用于缩小人工核查范围，最终销售回款口径仍需结合对手方、摘要、合同、发票和业务背景逐笔判断。

### 科目余额表分析

```bash
python3 scripts/review_trial_balance.py trial-balance.xlsx trial-balance-review.xlsx \
  --parent-digits 4
```

脚本会输出重大科目、前五大明细、科目变动和标准化余额表。若源文件列名特殊，可通过 `--help` 查看列名映射参数。

### 业务模式图

```bash
python3 scripts/render_business_flow.py flow.json business-flow.svg
```

`flow.json` 示例：

```json
{
  "title": "业务模式图",
  "nodes": [
    {"id": "supplier", "label": "供应商"},
    {"id": "company", "label": "申报企业"},
    {"id": "customer", "label": "客户"}
  ],
  "edges": [
    {"from": "supplier", "to": "company", "label": "原材料或服务", "type": "goods"},
    {"from": "company", "to": "supplier", "label": "采购付款", "type": "funds"},
    {"from": "company", "to": "customer", "label": "产品或服务", "type": "goods"},
    {"from": "customer", "to": "company", "label": "销售回款", "type": "funds"}
  ]
}
```

`funds` 类型使用红色箭头，`goods` 类型使用黑色箭头；脚本也支持灰色的 `info` 信息流。

### Word 成稿统一楷体

```bash
python3 scripts/enforce_docx_kaiti.py draft.docx final.docx
```

脚本会把 Word 正文、标题、表格、题注、页眉和页脚等可编辑文字统一设置为楷体；业务模式图本身也使用楷体字体栈。运行后仍需逐页渲染检查标题层级、表格和特殊符号是否正常。

## 隐私与数据安全

- 公开仓库仅保存技能规则和通用工具，不应提交任何真实客户材料、报告、流水、征信或个人信息。
- 建议在本地单独建立客户项目目录，并确认其不在 Git 仓库范围内。
- 对外部公开信息应保留来源和查询日期；对材料中的敏感信息应按照所在机构的数据管理要求处理。
- 本仓库的 `.gitignore` 已屏蔽常见文档、表格、PDF 和图片文件，但提交前仍应人工检查 `git status`。

## 使用边界

本技能用于辅助资料整理、分析、核查和报告起草，不替代授信政策、合规审查、专业判断或有权审批。使用者应复核事实、数字、公开信息、风险判断和最终授信方案，并对正式提交内容负责。
